- 기준 문서: `docs/VIDEO_ALGORITHM_DEVELOPMENT_PLAN.md`

## 작업 목적

기존의 단순 각도 임계값과 프레임 개수 기반 횟수 측정을 다음 문제에 더 안정적인 구조로 개선한다.

- 관절 confidence가 낮은 프레임에서 발생하는 잘못된 각도
- MoveNet 좌표의 프레임 간 흔들림
- 기기별 FPS 차이에 따른 판정 결과 변화
- 임계값 부근에서 발생하는 중복 횟수
- 운동 범위를 완료하지 않은 동작의 잘못된 카운트

## 구현 내용

### 1. 관절 confidence 검사

운동별 `angleJoints`에 지정된 모든 관절이 다음 조건을 충족해야 판정을 수행한다.

- 관절 객체가 존재함
- `x`, `y`, `score`가 유한한 숫자임
- confidence가 `0.4` 이상임
- 좌표가 비디오 프레임 내부에 있음

검사에 실패하면:

- 해당 프레임에서는 각도와 횟수를 갱신하지 않는다.
- invalid frame 통계를 증가시킨다.
- 사용자에게 관절 가림 또는 화면 이탈 원인을 안내한다.
- 개발자 도구에 마지막 실패 원인을 표시한다.

### 2. EMA 좌표 평활화

유효한 관절 좌표에 Exponential Moving Average를 적용했다.

```text
filtered = 0.35 × current + 0.65 × previous
```

적용 대상은 각 관절의 `x`, `y` 좌표이며 confidence는 현재 프레임 값을 유지한다.

필터는 다음 상황에서 초기화된다.

- 카메라 시작
- 카메라 종료
- 운동 변경
- 카운트 및 운동 상태 초기화

### 3. 안전한 각도 계산

- 두 벡터 중 하나의 길이가 0에 가까우면 각도를 반환하지 않는다.
- 계산 결과가 유한한 숫자인지 검사한다.
- 각도 계산 실패 프레임을 invalid frame으로 기록한다.

### 4. 시간 기준 각속도 계산

프레임 간 각도 차이를 그대로 사용하지 않고 경과 시간으로 나눠 초당 각도 변화량을 계산한다.

```text
angularVelocity = (currentAngle - previousAngle) / elapsedSeconds
```

현재 각속도는 개발자 도구에 `deg/s` 단위로 표시한다.

### 5. 시간 기반 횟수 상태 머신

기존 방식은 최저점과 시작점에서 각각 2프레임을 유지하면 횟수를 증가시켰다. 이 방식은 FPS에 따라 필요한 유지 시간이 달라지는 문제가 있었다.

새 상태는 다음과 같다.

```text
READY
  → BOTTOM_HOLD
  → RETURNING
  → READY + 1 rep
```

전환 조건:

1. `READY`에서 운동별 `down` 각도 이하를 180ms 유지
2. `BOTTOM_HOLD`에서 `down + 8°` 이상으로 복귀
3. `RETURNING`에서 운동별 `up` 각도 이상을 180ms 유지
4. 완전한 왕복 동작이 확인된 경우에만 1회 증가

`8°` 히스테리시스를 사용해 최저점 임계값 부근의 흔들림으로 상태가 반복 전환되는 것을 방지한다.

### 6. 장시간 invalid 상태 처리

필수 관절을 1초 이상 안정적으로 찾지 못하면 현재 반복의 상태 전환을 초기화한다.

- 이미 완료된 횟수는 유지한다.
- 진행 중이던 불완전 반복만 취소한다.
- 새로 관절이 검출되면 `READY`부터 다시 판정한다.

### 7. 개발자 도구 지표

기존 placeholder였던 개발자 도구에 다음 값을 실시간 표시하도록 연결했다.

- 현재 운동
- 횟수 상태 머신 단계
- 평활화된 관절 각도
- 각속도
- FPS
- valid frame 수
- invalid frame 수
- 유효 관절 검출률
- 마지막 관절 검증 결과
- EMA alpha
- 최소 confidence

### 8. 지원 운동 범위 제한

운동 선택 UI에는 현재 우선 검증 대상인 다음 두 운동만 노출한다.

- Right Arm Curl
- Squat

과거 운동 설정은 후속 정리와 비교를 위해 코드에 유지했지만, 실제 검증 전에는 사용자에게 지원 운동으로 표시하지 않는다.

### 9. Phase 0 잔여 TTS 코드 제거

Phase 0에서 TTS 본체를 제거한 뒤 남아 있던 다음 참조를 완전히 제거했다.

- `speakText`
- `countdownAudio`
- `ttsReady`
- `preloadCountdownAudio`

카운트다운은 화면 오버레이만 사용한다.

또한 카운트다운 시작 직후 `resetCounter()`가 `countdownActive`를 다시 `false`로 바꾸던 기존 순서 문제를 수정했다.

## 설정값

| 설정 | 현재 값 | 목적 |
|---|---:|---|
| 최소 관절 confidence | 0.4 | 낮은 신뢰도 좌표 배제 |
| EMA alpha | 0.35 | 관절 흔들림 감소 |
| 상태 유지 시간 | 180ms | 순간 임계값 통과 배제 |
| invalid 상태 초기화 | 1000ms | 가림 이후 불완전 반복 취소 |
| 히스테리시스 | 8° | 임계값 부근 상태 떨림 방지 |

이 값들은 초기값이며 실제 웹캠 테스트 결과에 따라 조정해야 한다.

## 남은 수동 검증

실제 MoveNet 좌표의 노이즈와 카메라 조건은 브라우저에서 확인해야 한다.

1. 정상 속도 팔 컬 10회의 측정 횟수
2. 빠른 팔 컬에서 최저점 누락 여부
3. 최저점에서 반동할 때 중복 횟수 여부
4. 손목 또는 팔꿈치를 가린 동안 횟수가 멈추는지
5. 가림이 1초 이상 지속된 후 불완전 반복이 취소되는지
6. EMA 적용으로 반응이 지나치게 느려지지 않는지
7. 스쿼트 10회의 최저점과 복귀점 임계값
8. 개발자 도구의 confidence와 valid rate 갱신

## 알려진 한계

- EMA alpha와 각도 임계값은 아직 실제 사용자 영상으로 조정하지 않았다.
- 필수 관절 세 개만 화면 범위를 검사하며, 신체 전체 크기와 촬영 거리는 아직 판단하지 않는다.
- 각속도는 측정하지만 현재 횟수 상태 전환 조건에는 직접 사용하지 않는다.
- 개발자 지표는 세션 누적값이며 Phase 3의 정식 성능 모니터링과 결과 내보내기는 아직 구현하지 않았다.
- 운동별 자세 오류 규칙은 기존 각도 피드백을 유지하고 있다.
