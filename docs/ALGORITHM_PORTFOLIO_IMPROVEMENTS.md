# Algorithm + 포트폴리오 개선점

## 문서 목적

현재 FitForm Live는 정상 Right Arm Curl 단일 세션에서
영상처리 파이프라인과 검증 결과를 재현 가능한 형태로 기록했다.

이 문서는 현재 결과로 증명할 수 있는 범위를 구분하고,
프로젝트를 단순 정상 동작 데모에서 조건별 영상 알고리즘 성능 검증 프로젝트로 발전시키기 위한
알고리즘·데이터·실험·포트폴리오 개선 방향을 정리한다.

기준 문서:

- `docs/CURL_NORMAL_VALIDATION_2026-07-28.md`
- `docs/PHASE_7_WORK_LOG.md`
- `web/js/pose-algorithms.js`

## 현재 포트폴리오의 강점

### JD 주요 업무와의 연결

현재 프로젝트는 다음 역량을 실제 코드와 측정 결과로 보여준다.

- 실시간 웹캠 프레임 처리
- MoveNet 기반 인체 관절 추정
- 관절 confidence와 화면 범위 검증
- OpenCV 기반 입력 영상 품질 분석
- 영상 판정 알고리즘 구현
- 모델·프레임 처리 성능 측정
- JSON·CSV 평가 결과 자동 저장
- 자동 회귀 테스트와 실패 조건 문서화

따라서 카메라 기반 영상처리 시스템 구현,
OpenCV와 AI 인체 인식 활용, 알고리즘 개발 및 성능 테스트 항목과 직접 연결된다.

### 정량 결과

정상 조건 단일 세션에서 다음 결과를 확보했다.

```text
실제 횟수: 10
예측 횟수: 10
절대 횟수 오차: 0
처리 프레임: 3,682
유효 관절 검출률: 77.8%
무효 프레임 비율: 22.2%
평균 추론시간: 15.51ms
P95 추론시간: 18.50ms
최대 추론시간: 96.10ms
추론 오류: 0
Processing FPS (EMA): 64.6
```

평균뿐 아니라 P50, P95와 최대값을 분리해 기록했고,
결과의 적용 범위와 미검증 조건을 숨기지 않았다는 점이 강점이다.

## 현재 결과의 정확한 의미

다음과 같이 설명할 수 있다.

> 정상 Right Arm Curl 단일 세션에서 전체 분석 프레임의 22.2%를 관절 유효성 조건에 따라 판정에서 제외한 상태에서도 실제 10회와 예측 10회가 일치했다.

다만 현재 결과만으로 다음 인과관계를 직접 증명할 수는 없다.

- confidence 필터가 횟수 오차를 줄였는가
- EMA가 중복 카운트를 줄였는가
- 히스테리시스가 임계값 노이즈를 제거했는가
- Hold time이 불완전 동작 오인식을 줄였는가
- OpenCV 품질값이 관절 검출률과 어떤 관계가 있는가

각 요소의 개선 효과를 주장하려면 동일 입력에 대한 ablation 결과가 필요하다.

## 핵심 문제 정의

포트폴리오의 메인 문제는 다음과 같이 유지한다.

> MoveNet의 관절 좌표가 흔들리고 일부 프레임에서 검출이 실패하는 환경에서도, 불완전 동작과 노이즈를 중복 카운트하지 않고 운동 횟수를 안정적으로 측정하려면 어떤 검증·평활화·상태 전이 구조가 필요한가?

포트폴리오 제목:

> 불완전한 자세 추정 결과를 신뢰 가능한 운동 횟수로 변환하는 실시간 영상처리 알고리즘

## 가장 중요한 알고리즘 개선

### 실제 관절 데이터 저장

사람이 같은 동작을 여러 번 재현하게 하면 속도, 각도와 가림 정도가 매번 달라진다.
알고리즘 구성을 공정하게 비교하려면 동일한 관절 시계열에 설정만 다르게 적용해야 한다.

다음 데이터를 저장하는 기능이 필요하다.

```json
{
  "testId": "curl-partial-01",
  "condition": "partial",
  "exercise": "right_curl",
  "attemptedReps": 5,
  "completeReps": 0,
  "frames": [
    {
      "timestampMs": 0,
      "keypoints": [
        {
          "name": "right_shoulder",
          "x": 0,
          "y": 0,
          "score": 0.92
        }
      ]
    }
  ]
}
```

영상 자체 대신 타임스탬프와 관절 좌표·confidence를 저장하면
개인 식별 가능성을 줄이면서 알고리즘 회귀 데이터셋을 구성할 수 있다.

### 시도 횟수와 완전 동작 횟수 분리

불완전 컬 5회를 수행했다면 다음 값을 구분해야 한다.

```text
attempted partial reps: 5
true complete reps: 0
predicted complete reps: 0
```

현재의 `trueReps` 하나만으로는
“5번 시도했지만 유효한 완전 반복은 0회”라는 테스트 의미를 충분히 표현할 수 없다.

### 오프라인 재실행기

저장된 관절 데이터를 카메라 없이 알고리즘에 다시 입력하는 runner가 필요하다.

```text
저장된 keypoint 시계열
  → 알고리즘 설정 선택
  → 프레임 순서대로 재실행
  → 상태 전이와 카운트 이벤트 기록
  → 실제 횟수와 예측 횟수 비교
```

브라우저 앱과 runner는 동일한 `web/js/pose-algorithms.js`를 사용해야 한다.

## 우선 수행할 조건별 테스트

모든 조건을 한 번에 수행하기보다 다음 세 조건을 우선한다.

### 1. 정상 컬

현재 완료된 baseline 조건이다.

비교 기준:

- 실제 횟수와 예측 횟수
- 유효 관절 검출률
- 추론시간
- OpenCV 밝기와 선명도

### 2. 불완전 컬

가장 우선순위가 높은 추가 테스트다.

기록할 값:

- 부분 동작 시도 횟수
- 실제 완전 동작 횟수
- 시스템 예측 횟수
- 부분 동작 오인식 횟수
- 상태 머신의 최대 도달 단계

이 테스트를 통해 하단 각도 조건, Hold time과 히스테리시스의 의미를 검증한다.

### 3. 관절 가림

다음 요소를 함께 확인할 수 있다.

- confidence 필터
- 무효 프레임 처리
- 1초 이후 미완료 상태 초기화
- 재검출 시 각속도 기준점 초기화
- 가림 이후 정상 판정 복구

### 후속 테스트

- 빠른 팔 컬
- 저조도 또는 흐림
- 정상 스쿼트

저조도 조건에서는 정상 조건 대비 밝기, 선명도,
유효 관절 검출률, 무효 프레임 비율과 카운트 오차의 변화를 관찰한다.

한두 세션의 결과만으로 상관관계나 인과관계를 일반화하지 않는다.

## Ablation test

현재 파이프라인은 여러 알고리즘 요소가 동시에 활성화되어 있다.
각 요소의 개선 효과를 분리하려면 동일 관절 입력을 다음 설정으로 재실행한다.

| 설정 | Confidence | EMA | Hysteresis | Hold time | 예측 횟수 | 절대 오차 | 중복 카운트 | 부분 동작 오인식 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Baseline | X | X | X | X | - | - | - | - |
| Validation | O | X | X | X | - | - | - | - |
| Smoothing | O | O | X | X | - | - | - | - |
| Stable FSM | O | O | O | O | - | - | - | - |

Baseline 알고리즘도 재현 가능하게 정의해야 한다.

```text
angle ≤ 60°가 한 번 감지됨
  → 이후 angle ≥ 155°가 한 번 감지됨
  → 1회 증가
```

동일 입력 데이터에 설정만 다르게 적용해야
각 필터가 오류를 줄였다는 인과관계를 비교할 수 있다.

## 시계열 그래프

포트폴리오에 다음 데이터를 한 그래프에 표현한다.

- Raw angle
- EMA-smoothed angle
- Down threshold
- Up threshold
- State transition
- Rep-count event
- Invalid-frame region

그래프가 보여줘야 하는 내용:

1. 원시 각도 노이즈가 EMA 이후 어떻게 달라졌는가
2. 임계값을 순간 통과한 값이 왜 상태 전이로 인정되지 않았는가
3. Hold time을 충족한 시점은 언제인가
4. 무효 프레임 구간에서 판정이 보류됐는가
5. 실제 카운트 이벤트가 어느 프레임에서 발생했는가

이 그래프는 단순 파이프라인 설명보다 알고리즘의 실제 동작을 더 직접적으로 보여준다.

## 조건별 결과 비교표

포트폴리오의 최종 결론은 다음 형식의 표로 구성한다.

| 조건 | 실제 횟수 | 예측 횟수 | 절대 오차 | 유효 관절 검출률 | 평균 추론 | P95 추론 | 밝기 | 선명도 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 정상 | 10 | 10 | 0 | 77.8% | 15.51ms | 18.50ms | 90.77 | 2,774.56 |
| 빠른 동작 | - | - | - | - | - | - | - | - |
| 불완전 동작 | - | - | - | - | - | - | - | - |
| 관절 가림 | - | - | - | - | - | - | - | - |
| 저조도 | - | - | - | - | - | - | - | - |

이 표가 채워지면 프로젝트는 정상 동작 데모가 아니라
조건 변화에 따른 영상 알고리즘 성능 검증 프로젝트가 된다.

## 지표와 표현 개선

### `정확도` 대신 `횟수 판정 결과`

단일 세션에서는 일반적인 의미의 정확도보다 다음 용어를 사용한다.

- True reps
- Predicted reps
- Session absolute rep error
- Exact-count match
- Within-one-rep

여러 세션을 확보한 이후 다음 통계를 계산한다.

- Mean Absolute Rep Error
- Exact-count Match Rate
- Within-one-rep Rate

반복 이벤트별 정답 라벨이 없으면 per-repetition precision과 recall을 주장하지 않는다.

### 유효 관절 검출률 정의

다음 정의를 문서와 포트폴리오에 표시한다.

> 전체 분석 프레임 중 해당 운동의 필수 관절이 최소 confidence와 화면 범위 조건을 모두 통과한 프레임 비율

```text
Valid Joint Rate
= Valid Frames / (Valid Frames + Invalid Frames)
```

### `EMA FPS` 명칭

현재 코드는 프레임 간 처리시간으로 계산한 FPS에 EMA를 적용한다.
따라서 다음 명칭을 사용한다.

```text
Processing FPS (EMA)
```

또는:

```text
Smoothed Processing FPS
```

이를 `Inference FPS`라고 표현하지 않는다.

### OpenCV 분석 설정 공개

현재 설정:

```text
quality analysis width: 240px
analysis interval: 1000ms
brightness warning threshold: 55
sharpness warning threshold: 80
sharpness metric: Laplacian standard deviation²
```

이 임계값은 실제 장비·조건별 실험으로 최적화된 값이 아니라 초기 기준값임을 명시한다.

### EMA 계수 설명

현재 설정:

```text
alpha = 0.35
filtered = 0.35 × current + 0.65 × previous
```

아직 파라미터 탐색이나 ablation 결과가 없으므로 최적값이라고 표현하지 않는다.

권장 설명:

> 실시간 반응성과 좌표 안정성의 균형을 위한 초기 경험적 값으로 0.35를 적용했으며, 후속 관절 데이터셋에서 파라미터별 오차와 반응 지연을 비교할 예정이다.

## 포트폴리오 핵심 성과 문장

현재 결과로 안전하게 사용할 수 있는 문장:

> MoveNet의 관절 좌표를 그대로 횟수 판정에 사용하지 않고, 필수 관절 confidence 검증, EMA 좌표 평활화, 각속도 이상치 필터, 유지시간·히스테리시스 기반 상태 머신을 적용했습니다. 정상 Right Arm Curl 단일 세션에서 전체 3,682프레임 중 22.2%의 무효 프레임을 판정에서 제외한 상태에서도 실제 10회와 예측 10회가 일치했으며, 평균 추론시간 15.51ms, P95 18.50ms, 추론 오류 0건을 기록했습니다.

Ablation과 조건별 테스트 이후 목표 문장:

> 정상·빠른 동작·불완전 동작·관절 가림 조건에서 동일한 관절 시계열을 기반으로 알고리즘 구성을 비교하고, baseline 대비 절대 횟수 오차와 부분 동작 오인식을 정량적으로 줄였습니다.

두 번째 문장은 실제 비교 결과가 확보된 이후에만 사용한다.

## 개발 우선순위

```text
1. 관절 좌표·confidence·타임스탬프 저장
2. attemptedReps와 completeReps 분리
3. 불완전 동작 데이터 수집
4. 관절 가림 데이터 수집
5. 동일 입력 기반 offline runner
6. 알고리즘 기능 플래그 구성
7. ablation 자동 실행
8. 각도·상태 전이 시계열 그래프 생성
9. 조건별 비교표 작성
10. HTML 포트폴리오 Evidence 섹션 갱신
```

## 최종 방향

포트폴리오의 중심 메시지는 다음과 같이 발전해야 한다.

```text
MoveNet 기반 운동 데모를 구현했다.
```

에서:

```text
실제 카메라에서 수집한 동일 관절 시계열을 이용해
후처리 알고리즘을 조건별로 비교하고,
각 구성 요소가 오카운트에 미치는 영향을 정량 검증했다.
```

이 방향이 알고리즘 개발 및 성능 테스트를 요구하는 JD와 가장 직접적으로 연결된다.
