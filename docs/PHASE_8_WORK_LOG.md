## 작업 목적

정상 팔 컬 검증 문서를 그대로 웹페이지로 옮기는 대신,
면접관이 짧은 시간 안에 다음 내용을 파악할 수 있는 기술 사례 연구로 재구성한다.

1. 어떤 영상 분석 문제가 있었는가
2. MoveNet 이후 어떤 알고리즘을 직접 구현했는가
3. 정상 조건에서 어떤 수치로 검증했는가
4. OpenCV가 어떤 역할을 담당하는가
5. 결과로 주장할 수 있는 범위와 한계는 무엇인가

## 정보 구조

포트폴리오는 다음 흐름으로 구성했다.

```text
Hero
  → System View
  → Root Cause
  → Resolution
  → Result
  → OpenCV
  → Scope
  → Engineering takeaway
```

### System View

전체 시스템을 세 가지 Mermaid 다이어그램으로 시각화했다.

1. Architecture: 카메라, MoveNet, 직접 구현 알고리즘, OpenCV와 결과 저장의 역할 관계
2. Data Flow: 필수 관절 유효성 분기, 무효 프레임 제외, 각속도 이상치 처리와 카운트 흐름
3. Sequence: 사용자 시작부터 프레임별 추론·판정·품질 분석·결과 내보내기의 시간 순서

다이어그램 아래에는 포트폴리오 본문의 흐름을 다음과 같이 안내한다.

```text
문제 원인 → 해결 과정 → 검증 결과
```

Mermaid 11 런타임은 외부 CDN 장애의 영향을 받지 않도록
`portfolio/vendor/mermaid-11.min.js`에 로컬 고정하고 MIT 라이선스 사본을 포함했다.

### Hero

프로젝트를 다음 한 문장으로 정의했다.

> 흔들리는 관절 좌표를 신뢰 가능한 1회로.

웹 운동 서비스보다 관절 좌표 후처리와 판정 알고리즘이 중심임을 첫 화면에서 드러낸다.

### Problem

다음 여섯 문제를 구분해 제시했다.

- 좌표 흔들림
- 관절 누락
- 중복 상태 전이
- 관절 재검출 시 좌표 점프
- 촬영 환경 변화
- 정량 검증 부재

### Algorithm

직접 구현한 범위를 네 단계로 요약했다.

1. confidence와 화면 범위를 이용한 관절 유효성 검사
2. EMA 기반 좌표 평활화
3. 벡터 내적 기반 각도 계산과 각속도 이상치 처리
4. 유지시간과 히스테리시스를 적용한 반복 횟수 상태 머신

`pose-algorithms.js`의 순수 함수와 상태 전이를 코드 및 다이어그램으로 표현했다.

### Evidence

JSON 스냅샷의 대표 수치를 사용했다.

```text
실제 횟수: 10
예측 횟수: 10
절대 오차: 0
유효 관절 검출률: 77.8%
무효 프레임 비율: 22.2%
EMA FPS: 64.6
평균 추론시간: 15.51ms
P95 추론시간: 18.50ms
추론 오류: 0
```

무효 프레임이 존재했음에도 해당 데이터를 판정에서 제외하고 정상 카운트를 유지했다는 점을 핵심 결과로 설명했다.

### OpenCV

OpenCV가 횟수 판정이 아니라 입력 영상 품질 분석을 담당한다는 역할 경계를 명시했다.

```text
밝기 평균: 90.77
Laplacian variance 선명도: 2,774.56
품질 분석시간: 5.6ms
```

### Scope

정상 조건 단일 테스트 결과를 전체 정확도로 일반화하지 않도록
현재 증명한 항목과 다음에 검증할 항목을 나누어 표시했다.

## 시각 설계

- 데이터와 알고리즘을 강조하는 에디토리얼 레이아웃
- 검정, 아이보리, 신호색 라임과 파랑의 제한된 색상 체계
- 실제 인물을 사용하지 않고 SVG 관절 스켈레톤을 직접 구성
- 큰 문제 정의와 정량 결과를 중심으로 정보 위계 설정
- 데스크톱, 태블릿, 모바일 반응형 레이아웃
- 스크롤 진행 표시와 화면 진입 애니메이션
- `prefers-reduced-motion` 환경에서 애니메이션 제거

기존 `images/pipeline.png`는 삭제한 ML 학습 루프가 포함되어 현재 프로젝트 범위와 맞지 않아 사용하지 않았다.

## 실행 방법

프로젝트 루트에서 정적 서버를 실행한다.

```powershell
python -m http.server 8766 --directory .
```

브라우저에서 다음 주소를 연다.

```text
http://localhost:8766/portfolio/
```

## 검증 결과

- 포트폴리오 경로 HTTP 200 확인
- 로컬 Mermaid.js 파일 HTTP 200 확인
- 인라인 JavaScript 문법 검사 통과
- Architecture, Data Flow, Sequence 다이어그램 소스 존재 확인
- Root Cause, Resolution, Result, Scope 및 대표 수치 존재 확인
- 다이어그램 탭 클릭 및 좌우 방향키 접근성 구현
- 라이브 데모 링크 HTTP 200 확인
- 원본 검증 문서 링크 HTTP 200 확인
- Git diff 공백 오류 검사 통과
- Chrome/Edge headless 캡처는 Windows GPU 프로세스 오류로 실행 환경에서 완료하지 못함

브라우저 캡처 실패는 페이지 HTTP 응답이나 JavaScript 오류가 아니라
headless 브라우저의 GPU 캐시 초기화 문제였다.
