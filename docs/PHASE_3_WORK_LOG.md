# Phase 3 작업 로그

## 작업 개요

- 작업일: 2026-07-27
- Phase: 3 — 성능 모니터링
- 기준 문서: `docs/VIDEO_ALGORITHM_DEVELOPMENT_PLAN.md`
- 변경 파일: `web/index.html`
- 상태: 계측, 통계 및 결과 내보내기 구현 완료, 실제 브라우저 측정 필요

## 작업 목적

실시간 영상처리 애플리케이션의 성능을 단순한 순간 FPS가 아닌 재현 가능한 수치로 기록한다.

이번 Phase에서 구분하여 측정하는 대상은 다음과 같다.

- MoveNet 모델 최초 로딩 시간
- 프레임별 MoveNet 추론 지연시간
- OpenCV 분석과 후처리를 포함한 전체 프레임 처리시간
- 안정화된 FPS
- 유효 관절 검출률
- 추론 오류 횟수

측정 결과는 JSON과 CSV로 내려받아 README 결과표와 면접 설명의 근거 자료로 사용할 수 있게 한다.

## 구현 내용

### 1. 모델 로딩 시간

`createDetector()` 호출 직전과 완료 직후의 `performance.now()` 차이를 기록한다.

```text
modelLoadMs = detectorReadyAt - detectorStartAt
```

이미 detector가 메모리에 있는 카메라 재시작에서는 다시 모델을 로드하지 않으므로 최초 측정값을 유지한다.

### 2. 추론 지연시간

각 프레임에서 다음 구간을 측정한다.

```text
estimatePoses 시작
  → MoveNet Promise 완료
  → inferenceMs 기록
```

MoveNet 추론 예외는 별도 `inferenceErrors` 값으로 증가시키고, 렌더 루프가 완전히 중단되지 않도록 다음 프레임을 예약한다.

### 3. 전체 프레임 처리시간

`renderLoop()` 시작부터 다음 프레임 예약 직전까지의 시간을 측정한다.

포함되는 작업:

- 주기적인 OpenCV.js 영상 품질 분석
- MoveNet 추론
- confidence 및 좌표 유효성 검사
- EMA 평활화
- 각도와 각속도 계산
- 상태 머신 갱신
- 스켈레톤 및 HUD 렌더링

따라서 `frameMs`와 `inferenceMs`의 차이를 통해 추론 외 후처리 및 렌더링 비용을 대략적으로 확인할 수 있다.

### 4. 워밍업 제외

세션 초기 5개 MoveNet 추론 프레임은 통계에서 제외한다.

초기 WebAssembly 및 TensorFlow.js 실행은 이후 프레임보다 느릴 수 있으므로, 정상 상태의 추론 지연시간을 왜곡하지 않기 위한 처리다.

제외된 워밍업 프레임 수는 결과 파일에 함께 기록한다.

### 5. 샘플 개수 제한

추론 및 프레임 처리시간은 각각 최대 3,000개까지 저장한다.

- 3,000개 초과 시 가장 오래된 샘플 제거
- 장시간 실행 시 JavaScript 배열의 무제한 증가 방지
- JSON 결과 파일 크기 제한

### 6. 지연시간 통계

추론시간과 전체 프레임 처리시간에 각각 다음 값을 계산한다.

- count
- average
- P50
- P95
- max

백분위수는 정렬된 배열에서 위치를 계산하고 두 인덱스 사이를 선형 보간한다.

### 7. 안정화된 FPS

순간 FPS 대신 EMA를 적용한다.

```text
fpsEma = 0.15 × instantFps + 0.85 × previousFpsEma
```

단일 프레임 지연에 따른 숫자 흔들림을 줄이고 최근 처리 성능의 추세를 표시한다.

HUD의 FPS도 EMA 값으로 변경했다.

### 8. 개발자 도구 갱신

다음 항목을 추가했다.

- EMA FPS
- 모델 로딩 시간
- 추론 average/P50/P95/max
- 전체 프레임 average/P50/P95/max
- 수집된 성능 샘플 수
- 남은 워밍업 프레임
- 추론 오류 횟수

통계 계산에는 배열 정렬이 포함되므로 개발자 도구 텍스트는 최대 250ms마다 한 번만 갱신한다.

### 9. JSON 내보내기

JSON 결과에는 다음 구조가 포함된다.

```text
schemaVersion
generatedAt
exercise / mode
session
environment
model
performance
frameQuality
configuration
samples
```

주요 내용:

- 세션 시간과 반복 횟수
- 처리/유효/무효 프레임 수
- 유효 관절 검출률
- 브라우저 user agent와 영상 해상도
- 모델 로딩 시간
- FPS와 지연시간 통계
- OpenCV 품질 분석 결과
- 사용한 알고리즘 임계값
- 원본 추론 및 프레임 처리시간 샘플

### 10. CSV 내보내기

CSV는 세션 요약을 한 행으로 저장한다.

- UTF-8 BOM 포함
- Excel에서 한국어 호환
- 쉼표, 따옴표 및 줄바꿈 escape 처리
- 추론 및 프레임 통계 포함

파일명 예시:

```text
fitform-right_curl-2026-07-27T00-00-00-000Z.json
fitform-right_curl-2026-07-27T00-00-00-000Z.csv
```

### 11. 개발자 도구 버튼

다음 버튼을 추가했다.

- JSON 결과 저장
- CSV 결과 저장
- 성능 지표 초기화

성능 지표 초기화는 detector를 다시 로드하지 않으며 기존 모델 로딩 시간은 보존한다.

## 남은 수동 검증

실제 브라우저에서 다음 내용을 확인해야 한다.

1. 모델 최초 로딩 시간이 기록되는지
2. 첫 5개 프레임이 추론 통계에서 제외되는지
3. 추론 P50/P95가 세션 중 정상 갱신되는지
4. OpenCV 분석 프레임에서 전체 frameMs가 증가하는지
5. JSON 파일이 정상적으로 다운로드되고 다시 파싱되는지
6. CSV 파일이 Excel에서 열리는지
7. 영상 해상도와 user agent가 정확히 기록되는지
8. 성능 지표 초기화 후 샘플 수가 0으로 돌아가는지
9. 개발자 도구 250ms 제한이 화면 반응성에 미치는 영향
10. 계측 활성화 전후 FPS 차이

## 알려진 한계

- 현재 상태 전환 이력은 결과 파일에 포함하지 않았다.
- 전체 프레임 시간은 `requestAnimationFrame` 대기시간을 포함하지 않는다.
- FPS는 렌더 루프 시작 시점 간 차이를 사용하므로 브라우저 스케줄링 영향을 받는다.
- 최대 3,000개 이후에는 오래된 샘플이 제거되므로 매우 긴 세션의 전체 통계가 아니다.
- 백그라운드 탭에서는 브라우저가 `requestAnimationFrame`을 제한할 수 있다.
- 성능 계측 자체에도 작은 실행 비용이 있다.
