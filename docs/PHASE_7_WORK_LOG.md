## JD 요구사항과 작업 방향

공고의 프로젝트 관련 요구사항은 다음과 같다.

| JD 요구사항 | 프로젝트에서 제시할 증거 |
|---|---|
| AI 영상처리 데이터셋 구축 및 애플리케이션 성능 테스트 | 고정 각도 시퀀스 fixture, 조건별 JSON/CSV 결과, 지연시간·FPS·오차 측정 |
| 카메라 기반 영상처리 시스템 구현 및 성능 테스트 | 웹캠 입력, MoveNet 자세 추정, OpenCV 품질 분석, 프레임·추론 성능 통계 |
| 알고리즘 개발 프로젝트 경험 | EMA, 관절 검증, 각도·각속도 계산, 시간 기반 반복 횟수 상태 머신 |
| OpenCV 사용 경험 | 밝기 평균과 Laplacian variance 기반 선명도 측정 |
| AI 기반 객체인식 사용 경험 | MoveNet SinglePose Lightning 기반 인체 관절 검출 |

웨어러블 센서 신호처리, 골프 도메인 및 Python/C++ 역량은 이 프로젝트만으로 직접 증명하지 않는다.
지원 문서에서는 구현하지 않은 항목을 과장하지 않고 카메라 영상처리와 알고리즘 성능 검증 경험에 집중한다.

## 문제 정의

기존에는 UI, 브라우저 제어 및 핵심 판정 알고리즘이 `web/index.html`에 함께 있었다.
따라서 각도 임계값이나 상태 머신을 변경할 때 실제 카메라 테스트에 의존해야 했고,
과거에 정상 동작한 조건이 유지되는지 자동으로 확인하기 어려웠다.

## 구조 개선

다음 핵심 로직을 `web/js/pose-algorithms.js`로 분리했다.

- 세 점을 이용한 관절 각도 계산
- 시간 간격과 최대값을 이용한 각속도 이상치 필터
- 유지시간과 히스테리시스를 적용한 반복 횟수 상태 머신

브라우저 앱과 Vitest가 같은 파일을 사용한다.
테스트를 위해 알고리즘을 복사한 것이 아니므로 자동 테스트 결과가 실제 앱 로직을 직접 검증한다.

## 테스트 구성

### 단위 테스트

`tests/unit/pose-algorithms.test.js`에서 다음을 검증한다.

1. 직각 관절의 90도 계산
2. 길이가 0인 벡터 예외 처리
3. 정상 각속도 계산
4. 지나치게 짧은 시간 간격 제외
5. 지나치게 긴 시간 간격 제외
6. 최대 각속도 초과 좌표 점프 제외
7. 완전 동작 1회 판정
8. 불완전 동작 제외
9. 임계값을 순간 통과하는 노이즈 제외

### 결정론적 시퀀스 회귀 테스트

`tests/fixtures/right-curl-two-reps.json`에 시간과 팔꿈치 각도로 구성된
합성 팔 컬 2회 시퀀스를 고정했다.

`tests/integration/recorded-angle-sequence.test.js`는 이 시퀀스를 상태 머신에 입력해
항상 2회로 판정되는지 확인한다.

현재 fixture는 실제 영상에서 수집한 데이터가 아니라 알고리즘 경계조건 검증을 위한 합성 데이터다.
후속 단계에서는 실제 카메라에서 MoveNet 관절 좌표를 익명 JSON으로 저장해 회귀 데이터셋으로 확장한다.

## 실행 방법

최초 한 번 의존성을 설치한다.

```powershell
npm install
```

전체 자동 테스트를 실행한다.

```powershell
npm.cmd test
```

PowerShell 실행 정책이 `npm.ps1`을 차단할 수 있으므로 Windows에서는 `npm.cmd`를 사용한다.

개발 중 감시 모드는 다음과 같다.

```powershell
npm.cmd run test:watch
```

## 포트폴리오에서 설명할 핵심

> 브라우저 UI와 영상 판정 알고리즘을 분리하고, 실제 애플리케이션과 자동 테스트가 동일한 알고리즘 모듈을 사용하도록 구성했다. 관절 각도, 각속도 이상치, 상태 머신의 유지시간·히스테리시스 경계조건을 단위 테스트하고, 고정 입력 시퀀스로 반복 횟수 회귀를 검증했다.

이 작업은 단순 테스트 도구 도입보다 영상 알고리즘의 입력, 중간값,
판정 결과를 재현 가능한 형태로 검증했다는 점을 강조한다.
