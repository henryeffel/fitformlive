# Phase P3-C — Human Cycle Review

Date: 2026-07-30

## Outcome

The Streamlit annotation app can now load the
`*.review-candidate.json` files generated by `npm run video:compare`.
Machine-generated timestamps do not become ground truth automatically.

The reviewer must:

1. upload the matching schema 1.2 session JSON and video,
2. upload its review-candidate JSON,
3. select one candidate source,
4. inspect and adjust the suggested cycle interval against the video,
5. explicitly check `Human approved`, and
6. add only the approved rows to the annotation document.

The candidate section also provides `Download N reviewed annotations`.
This directly downloads the checked rows and avoids requiring the reviewer to
first copy them into Streamlit session state. The top-level `Annotations`
metric changes only when `Add approved rows to annotations` is used.

## Candidate sources

- `production_rep`: browser-recorded `REP_COUNTED` timestamps
- `exploratory_rep`: full-contraction FSM rep timestamps
- `exploratory_rejection`: full-contraction FSM incomplete-motion rejections

Production candidates come from the browser event log, not the diagnostic
keypoint recomputation.

Candidate sources are reviewed separately because production and exploratory
timestamps may describe the same physical repetition. Importing both without
review would create duplicate or overlapping annotations.

## Ground-truth boundary

Before approval:

```text
labelStatus = machine_generated_review_candidate
```

After explicit approval, the selected row becomes a schema 1.0
`CycleAnnotation` containing:

- reviewer-adjusted `startMs` and `endMs`
- `completionMs` only for `valid_rep`
- the human annotator identifier
- a note preserving the candidate identifier

The existing annotation schema still rejects overlapping cycles and invalid
completion timestamps.
