# FitForm Live 영상처리 알고리즘 개발 계획

## 1. 문서 목적

이 문서는 FitForm Live를 채용 공고의 **카메라 기반 영상처리 시스템 구현 및 성능 테스트** 역량에 맞게 개선하기 위한 기준 문서다.

개발 중 기능 범위가 불필요하게 확장되지 않도록 다음 내용을 관리한다.

- 프로젝트의 최종 방향
- 제거하거나 유지할 기능
- 영상처리 알고리즘 설계
- OpenCV.js 활용 범위
- 구현 순서와 완료 조건
- 성능 측정 및 결과 기록 방법
- README와 지원 자료에 사용할 설명

시간이 제한되어 있으므로 데이터 수집, 라벨링, 자체 ML 모델 학습은 범위에서 제외한다.

---

## 2. 프로젝트 재정의

### 한 문장 소개

> MoveNet과 OpenCV.js를 활용하여 웹캠 영상의 입력 품질과 인체 관절을 실시간으로 분석하고, 좌표 평활화 및 시간 기반 상태 머신으로 운동 횟수와 자세 상태를 판정하는 브라우저 기반 영상처리 시스템

### 핵심 목표

1. 웹캠 영상을 안정적으로 입력받는다.
2. 영상의 밝기와 선명도를 분석한다.
3. MoveNet으로 신체 관절 좌표를 추정한다.
4. 신뢰도가 낮은 관절과 프레임을 판정에서 제외한다.
5. 좌표 노이즈를 감소시켜 각도 계산을 안정화한다.
6. 프레임률 변화에 강한 상태 머신으로 운동 횟수를 측정한다.
7. 처리 속도와 유효 검출률을 실시간으로 측정한다.
8. 제한된 환경에서 기능 검증 결과를 기록하고 재현 가능하게 만든다.

### 프로젝트 파이프라인

```text
웹캠 프레임
  → OpenCV.js 입력 품질 분석
  → MoveNet 관절 추정
  → 관절 confidence 검사
  → 좌표 평활화
  → 관절 각도 및 움직임 특징 계산
  → 시간 기반 상태 머신
  → 횟수/자세/촬영환경 피드백
  → 성능 지표 기록
```

- 관절 및 스켈레톤 오버레이
- 운동 선택
- 관절 각도 표시
- 운동 횟수 측정
- 실시간 상태 피드백

### 제거 대상

- `classification model/`의 RandomForest 학습 및 모델 파일
- 메인 애플리케이션과 연결되지 않은 ML 실험 데이터
- 사용하지 않는 `avatar/main.js`
- 3D 아바타 관련 UI, Three.js 의존성 및 GLB 로딩 코드
- 프로젝트 핵심과 무관한 Azure TTS 기능

> 삭제 전에는 메인 실행 파일이 해당 파일이나 리소스를 참조하는지 반드시 검색한다. 삭제 작업은 기능별로 나누어 수행하고 매 단계에서 앱을 실행한다.

- 사용자 인증, 데이터베이스 및 배포 인프라
- 의료적 정확성 또는 부상 방지 효과 주장

## 5. 영상처리 및 판정 알고리즘

### 5.1 프레임 품질 분석

OpenCV.js는 실제 판정 신뢰도를 개선하는 용도로 사용한다.

#### 밝기 측정

- 입력 프레임을 grayscale로 변환한다.
- 전체 픽셀 평균을 밝기 값으로 사용한다.
- 임계값보다 낮으면 `LOW_LIGHT` 경고를 표시한다.
- 밝기가 낮아도 운동 횟수 판정을 즉시 중단할지는 테스트 후 결정한다.

#### 선명도 측정

- grayscale 프레임에 Laplacian을 적용한다.
- Laplacian 결과의 분산을 선명도 값으로 사용한다.
- 값이 기준보다 낮으면 `BLURRY_FRAME` 경고를 표시한다.

#### 실행 주기

OpenCV 처리는 매 프레임 수행하지 않고 기본적으로 5~10프레임마다 실행한다. 이 주기는 성능 측정 결과에 따라 조정한다.

#### 메모리 관리

OpenCV.js의 모든 `cv.Mat` 객체는 사용 후 `delete()` 한다. 반복 루프에서 메모리 누수가 발생하지 않는지 확인한다.

### 5.2 관절 신뢰도 검사

운동별로 필요한 관절을 정의하고 모든 관절이 최소 confidence를 충족할 때만 판정한다.

예시:

```text
Right Arm Curl: rightShoulder, rightElbow, rightWrist
Squat: hip, knee, ankle 및 상체 정렬에 필요한 어깨
```

초기 기준값은 `0.4`로 설정하고 실제 카메라 테스트를 통해 조정한다.

신뢰도가 부족하면:

- 횟수를 증가시키지 않는다.
- 상태 머신을 즉시 초기화하지 않고 짧은 유예 시간을 둔다.
- `관절이 잘 보이도록 위치를 조정하세요` 안내를 표시한다.
- invalid frame 통계를 증가시킨다.

### 5.3 촬영 위치 검사

정규화된 관절 좌표와 신체 비율을 이용해 다음 조건을 검사한다.

- 필요한 관절이 화면 안에 있는가
- 사용자가 너무 멀거나 가까운가
- 몸의 중심이 화면을 지나치게 벗어나지 않았는가
- 운동 판정에 적합한 방향으로 서 있는가

고정 픽셀값보다 영상 너비와 높이에 대한 비율을 사용한다.

### 5.4 EMA 좌표 평활화

관절별 `x`, `y` 좌표에 Exponential Moving Average를 적용한다.

```text
filtered = alpha × current + (1 - alpha) × previous
```

- 초기 `alpha`: `0.35`
- confidence는 좌표와 별도로 유지한다.
- 카메라 재시작, 운동 변경 및 장시간 검출 실패 시 필터를 초기화한다.
- 원본 각도와 필터 적용 각도를 개발자 모드에서 비교할 수 있게 한다.

### 5.5 각도 및 움직임 계산

- 각도 계산 전 세 관절의 confidence를 확인한다.
- 0으로 나누는 상황과 잘못된 좌표를 방어한다.
- 각도뿐 아니라 시간당 각도 변화량을 계산한다.

```text
angularVelocity = (currentAngle - previousAngle) / deltaTime
```

동작 방향 판정에 단순한 프레임 간 차이보다 시간 기준 변화량을 사용한다.

### 5.6 시간 기반 상태 머신

FPS가 다른 환경에서도 동일하게 작동하도록 프레임 개수가 아닌 경과 시간을 사용한다.

#### Right Arm Curl 상태 예시

```text
READY
  → FLEXING
  → BOTTOM_HOLD
  → EXTENDING
  → COMPLETE
  → READY
```

기본 전환 조건:

- `READY`: 팔이 충분히 펴진 상태가 일정 시간 유지됨
- `FLEXING`: 각도가 감소하며 팔을 굽히는 중
- `BOTTOM_HOLD`: 최소 굽힘 각도에 도달하여 짧게 유지
- `EXTENDING`: 각도가 증가하며 팔을 펴는 중
- `COMPLETE`: 다시 충분히 펴진 상태에 도달했을 때 1회 증가

완전한 왕복 동작을 마쳤을 때만 횟수를 증가시킨다.

#### 안정화 규칙

- 한 상태 전환 조건이 약 `150~300ms` 유지될 때 전환한다.
- 순간적인 confidence 저하는 짧은 유예 시간 동안 상태를 유지한다.
- 너무 긴 시간 동안 관절을 찾지 못하면 `READY`로 초기화한다.
- 운동 변경 및 카메라 재시작 시 상태를 초기화한다.

### 5.7 자세 피드백

피드백은 단순한 `Good/Bad` 대신 원인을 설명한다.

Right Arm Curl 예시:

- 시작 자세가 준비되지 않음
- 운동 범위가 부족함
- 완전히 펴기 전에 다음 반복을 시작함
- 팔꿈치 위치가 크게 이동함
- 동작이 지나치게 빠름
- 필요한 관절이 가려짐
- 촬영 환경이 어둡거나 흐림

피드백 규칙과 반복 횟수 판정 규칙을 분리하여, 잘못된 자세라도 동작 자체가 완료되었는지 독립적으로 판단할 수 있게 한다.

## 6. 성능 측정 설계

별도의 학습 데이터 없이도 **실시간 시스템 성능과 제한된 기능 검증**을 수행한다.

### 6.1 자동 측정 지표

- 전체 처리 프레임 수
- 자세가 검출된 프레임 수
- 필수 관절이 유효한 프레임 수
- 유효 관절 검출률
- 평균 FPS
- 평균 추론 지연시간
- P50 추론 지연시간
- P95 추론 지연시간
- 최대 추론 지연시간
- 밝기 경고 프레임 수
- 흐림 경고 프레임 수
- 상태 전환 이력
- 측정된 반복 횟수

### 6.2 측정 구간

- 모델 로딩 시간은 프레임 추론 지연시간과 분리한다.
- 워밍업 프레임은 평균 지연시간 집계에서 제외한다.
- MoveNet 추론 시간과 전체 렌더 루프 시간을 가능하면 별도로 측정한다.
- FPS는 순간값뿐 아니라 일정 구간의 이동평균으로 표시한다.

### 6.3 P95 계산

최근 또는 전체 세션의 지연시간을 오름차순으로 정렬하여 95번째 백분위 값을 사용한다. 샘플 개수를 결과와 함께 기록한다.

### 6.4 간단한 기능 검증

대규모 데이터셋 대신 통제된 환경에서 본인이 직접 반복 수행한다.

권장 테스트:

| 테스트 | 조건 |
|---|---|
| 기본 동작 | 팔 컬 10회 |
| 동작 범위 부족 | 절반만 굽히기 |
| 중간 정지 | 동작 중 1초 이상 멈추기 |
| 빠른 동작 | 의도적으로 빠르게 수행 |
| 낮은 조도 | 조명을 낮춰 수행 |
| 부분 가림 | 손목 또는 팔꿈치를 잠시 가림 |
| 거리 변화 | 카메라에서 너무 멀거나 가깝게 이동 |

각 테스트에서 실제 횟수와 측정 횟수를 수동으로 기록한다.

```csv
test_id,exercise,condition,true_reps,predicted_reps,avg_fps,avg_latency_ms,p95_latency_ms,valid_joint_rate,notes
```

### 6.5 결과 표현 원칙

- 테스트 환경, 브라우저, CPU, 카메라 해상도를 함께 기록한다.
- 결과를 일반적인 모델 정확도로 표현하지 않는다.
- `단일 사용자 및 제한된 촬영 환경에서 수행한 기능 검증`임을 명시한다.
- 실제 측정 전에는 README에 임의의 성능 수치를 작성하지 않는다.
- 실패 조건과 한계도 함께 기록한다.

## 9. 각 Phase의 완료 기준

### Phase 0 완료 기준

- 개발자 콘솔에 치명적인 오류가 없다.
- 웹캠 시작과 종료가 정상 동작한다.
- MoveNet이 관절을 추정하고 스켈레톤을 표시한다.
- 제거한 기능의 버튼, import, 파일 참조가 남아 있지 않다.

### Phase 1 완료 기준

- confidence가 낮을 때 횟수가 증가하지 않는다.
- 팔을 굽혔다가 다시 펴야 1회로 인정된다.
- 경계 각도 부근에서 횟수가 중복 증가하지 않는다.
- FPS가 달라져도 상태 전환 시간이 크게 변하지 않는다.
- 필터 리셋 조건이 정상 동작한다.

### Phase 2 완료 기준

- 어두운 환경과 흐린 영상에서 각각 경고가 표시된다.
- OpenCV 미로딩 상태에서 앱 전체가 중단되지 않는다.
- 카메라를 일정 시간 실행해도 지속적인 메모리 증가가 관찰되지 않는다.
- OpenCV 분석이 실시간 추론을 과도하게 방해하지 않는다.

### Phase 3 완료 기준

- 평균, P50, P95 지연시간이 표시된다.
- FPS와 유효 관절 검출률이 계산된다.
- 세션 결과를 파일로 저장할 수 있다.
- 워밍업 및 모델 로딩 시간이 추론 통계와 구분된다.

### Phase 4 완료 기준

- 테스트 환경과 조건이 문서화되어 있다.
- 실제 횟수와 측정 횟수가 함께 기록되어 있다.
- 성공 사례뿐 아니라 실패 사례도 포함되어 있다.
- README에 기재한 모든 숫자를 결과 파일로 확인할 수 있다.

## 11. 지원서 및 면접 설명

### 권장 프로젝트 설명

> 브라우저 웹캠 영상에서 MoveNet으로 인체 관절을 추정하고, OpenCV.js로 입력 영상의 밝기와 선명도를 분석하는 실시간 자세 분석 시스템을 구현했습니다. 관절 confidence 검사와 EMA 평활화를 적용해 좌표 노이즈를 줄였으며, 프레임 개수가 아닌 경과 시간 기반 상태 머신을 설계하여 기기별 FPS 차이와 순간 오검출에 강한 운동 횟수 판정 로직을 구현했습니다. 또한 평균 FPS, 추론 지연시간의 P50/P95 및 유효 관절 검출률을 측정해 제한된 환경에서 시스템 성능을 검증했습니다.

### 예상 질문

#### 왜 자체 ML 모델을 학습하지 않았는가?

> 이번 프로젝트의 목표를 모델 학습보다 실시간 카메라 입력의 안정적인 처리와 자세 추정 결과의 후처리 문제로 정의했습니다. 사전 학습된 MoveNet의 관절 좌표를 사용하고, 신뢰도 검사, 좌표 평활화, 시간 기반 상태 머신 및 입력 품질 분석을 직접 설계했습니다.

#### OpenCV를 어디에 사용했는가?

> OpenCV.js로 grayscale 평균 밝기와 Laplacian variance를 계산하여 낮은 조도와 흐린 입력을 감지했습니다. 입력 품질 분석은 일정 프레임 주기로 수행하여 실시간 추론 성능에 미치는 영향도 함께 측정했습니다.

#### 정확도를 어떻게 검증했는가?

> 대규모 학습 데이터셋 기반 모델 평가가 아니라 제한된 기능 검증을 수행했습니다. 통제된 조건에서 실제 반복 횟수와 측정 횟수를 비교했고, FPS, 평균/P95 추론 지연시간, 유효 관절 검출률 및 실패 조건을 기록했습니다.

#### 가장 중요한 알고리즘 개선은 무엇인가?

> 단일 각도 임계값만 사용하던 방식에서 confidence 검사, EMA 평활화, 히스테리시스 및 시간 기반 상태 머신을 결합한 방식으로 변경했습니다. 완전한 왕복 동작을 마쳤을 때만 횟수를 인정하여 경계값 부근의 중복 카운트를 줄였습니다.

## 12. 개발 원칙

1. 기능 수보다 알고리즘의 안정성과 설명 가능성을 우선한다.
2. 측정하지 않은 성능을 주장하지 않는다.
3. 모든 임계값은 상수로 흩어놓지 않고 운동별 설정에서 관리한다.
4. 임계값을 변경할 때 이유와 테스트 결과를 기록한다.
5. 렌더링, 추론, 판정 및 성능 측정 책임을 분리한다.
6. confidence가 낮은 데이터를 억지로 판정하지 않는다.
7. OpenCV는 기술 스택 표시용이 아니라 입력 품질 분석에 사용한다.
8. 브라우저와 하드웨어에 따라 결과가 달라질 수 있음을 명시한다.
9. 지원서, README 및 실제 코드의 설명을 일치시킨다.
10. 매 Phase 완료 후 기존 기능이 유지되는지 다시 확인한다.
