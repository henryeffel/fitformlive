# FitForm Live 수동 기능 검증 프로토콜

## 목적

이 문서는 FitForm Live의 횟수 판정, 관절 검출 안정성, 영상 품질 경고 및 실시간 처리 성능을 제한된 환경에서 일관되게 검증하기 위한 절차다.

이 검증은 대규모 데이터셋 기반 모델 정확도 평가가 아니다. 단일 사용자 또는 소수 사용자가 통제된 조건에서 수행하는 기능 검증이다.

## 테스트 전 준비

1. 노트북을 전원에 연결한다.
2. 성능에 영향을 주는 불필요한 프로그램과 브라우저 탭을 종료한다.
3. 카메라를 흔들리지 않는 위치에 고정한다.
4. 전신 또는 운동에 필요한 관절이 화면에 들어오는 거리를 확보한다.
5. 브라우저 확대/축소를 100%로 맞춘다.
6. 동일한 브라우저와 카메라 해상도를 모든 비교 테스트에서 유지한다.
7. 테스트 시작 전 개발자 도구에서 성능 지표를 초기화한다.

## 환경 기록

각 테스트 세션에서 다음 정보를 기록한다.

- 테스트 날짜와 시간
- 운영체제
- 브라우저와 버전
- CPU 또는 노트북 모델
- 카메라 해상도
- 조명 조건
- 카메라와 사용자 사이의 거리
- 운동 종류
- 테스트 조건

브라우저 user agent와 실제 영상 해상도는 JSON 결과에 자동 저장된다.

## 앱 사용 순서

1. 로컬 HTTP 서버로 `web/` 폴더를 실행한다.
2. FitForm Live를 열고 카메라 권한을 허용한다.
3. `카메라 시작`을 누른다.
4. 개발자 도구에서 OpenCV.js 상태가 `ready`인지 확인한다.
5. 테스트 ID와 조건, 실제 수행할 횟수를 입력한다.
6. `성능 지표 초기화`를 누른다.
7. 트레이닝 화면으로 돌아가 운동을 시작한다.
8. 정해진 횟수를 수행한다.
9. 운동을 정지한다.
10. 개발자 도구에서 예측 횟수와 실제 횟수를 확인한다.
11. JSON과 CSV 결과를 저장한다.
12. 특이사항을 테스트 메모에 기록한다.

## 기본 테스트 시나리오

### 1. 정상 팔 컬

- 테스트 ID: `curl-normal-01`
- 운동: Right Arm Curl
- 실제 횟수: 10회
- 조건: 정상 조명, 정상 속도, 완전한 운동 범위
- 확인 사항:
  - 완전히 굽혔다가 다시 편 동작만 카운트되는가
  - 측정 횟수가 실제 횟수와 일치하는가
  - 유효 관절 검출률이 안정적인가

### 2. 동작 범위 부족

- 테스트 ID: `curl-partial-01`
- 운동: Right Arm Curl
- 실제 수행 시도: 10회
- 조건: 팔꿈치를 최저점 임계값까지 굽히지 않음
- 기대 결과:
  - 불완전한 동작이 정상 횟수로 카운트되지 않아야 함

이 테스트에서 `true_reps`는 시도 횟수보다 올바르게 완료한 횟수를 기록한다. 모두 불완전한 동작이면 `0`으로 기록한다.

### 3. 빠른 동작

- 테스트 ID: `curl-fast-01`
- 운동: Right Arm Curl
- 실제 횟수: 10회
- 조건: 의도적으로 빠르게 수행
- 확인 사항:
  - 180ms 유지 조건 때문에 정상 동작을 과도하게 누락하는가
  - EMA가 빠른 움직임을 지나치게 지연시키는가

### 4. 낮은 조도

- 테스트 ID: `curl-low-light-01`
- 운동: Right Arm Curl
- 실제 횟수: 10회
- 조건: 실내 조명을 낮춤
- 확인 사항:
  - 평균 밝기가 55 미만으로 감소하는가
  - 낮은 조도 경고가 표시되는가
  - 유효 관절 검출률이 정상 환경보다 얼마나 감소하는가

### 5. 관절 일부 가림

- 테스트 ID: `curl-occlusion-01`
- 운동: Right Arm Curl
- 조건: 동작 중 손목 또는 팔꿈치를 약 2초간 가림
- 확인 사항:
  - confidence 부족 안내가 표시되는가
  - 가림 중 횟수가 증가하지 않는가
  - 1초 후 진행 중이던 불완전 반복이 취소되는가
  - 관절이 다시 보일 때 새 반복을 정상 측정하는가

### 6. 거리 변화

- 테스트 ID: `curl-distance-01`
- 운동: Right Arm Curl
- 조건: 카메라에서 지나치게 멀거나 가까운 위치로 이동
- 확인 사항:
  - 필수 관절의 화면 이탈을 감지하는가
  - 관절이 화면 밖인 상태에서 횟수가 증가하지 않는가

### 7. 정상 스쿼트

- 테스트 ID: `squat-normal-01`
- 운동: Squat
- 실제 횟수: 10회
- 조건: 측면 또는 약간 비스듬한 촬영, 정상 조명
- 확인 사항:
  - 최저점 100°와 복귀점 165°가 실제 동작에 적절한가
  - 좌우 다리 중 현재 사용하는 왼쪽 관절이 안정적으로 보이는가

## 임계값 조정 순서

한 번에 하나의 값만 변경한다.

1. 현재 설정으로 기본 테스트를 수행한다.
2. JSON과 CSV를 저장한다.
3. 문제 유형을 기록한다.
4. 하나의 임계값만 변경한다.
5. 동일한 조건과 횟수로 다시 테스트한다.
6. 변경 전후 결과를 비교한다.

조정 후보:

| 설정 | 현재 값 | 확인할 문제 |
|---|---:|---|
| confidence | 0.4 | 관절 검출 누락 또는 잘못된 좌표 |
| EMA alpha | 0.35 | 흔들림과 반응 지연의 균형 |
| 상태 유지시간 | 180ms | 반동 중복과 빠른 동작 누락 |
| 히스테리시스 | 8° | 최저점 부근 상태 떨림 |
| 최소 밝기 | 55 | 정상 환경의 잘못된 경고 |
| 최소 선명도 | 80 | 배경에 따른 잘못된 흐림 경고 |

## 결과 판정

각 테스트에서 다음 값을 확인한다.

```text
absolute_error = |predicted_reps - true_reps|
```

요약 지표:

- 정확 일치: `absolute_error = 0`
- ±1회 이내: `absolute_error ≤ 1`
- 유효 관절 검출률
- 평균/P95 추론시간
- EMA FPS
- 밝기와 선명도

## 결과 기록 위치

- 앱에서 내려받은 원본 JSON/CSV: `evaluation/results/`
- 전체 테스트 요약: `evaluation/test-results.csv`
- 빈 템플릿: `evaluation/test-results-template.csv`

개인 얼굴이 포함된 원본 카메라 영상은 별도 동의 없이 Git 저장소에 커밋하지 않는다.

## 결과 표현 시 주의사항

- 테스트 사용자 수와 테스트 횟수를 반드시 명시한다.
- 제한된 환경에서 수행한 기능 검증이라고 표현한다.
- 실패 조건을 숨기지 않는다.
- 측정하지 않은 정확도를 주장하지 않는다.
- 서로 다른 장비의 결과를 직접 비교할 때 환경 차이를 함께 기록한다.
