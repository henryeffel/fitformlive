# Phase 6 작업 로그

## 작업 개요

- 작업일: 2026-07-28
- Phase: 6 — 각속도 이상치 처리
- 기준 결과: `docs/OPENCV_DEBUG_TEST_LOG_2026-07-28.md`
- 변경 파일: `web/index.html`
- 상태: 구현 및 정적 검증 완료, 실제 브라우저 회귀 테스트 필요

## 작업 목적

OpenCV.js 디버깅 후 팔 컬 10회는 정확히 인식했지만,
개발자 로그에서 다음과 같은 비현실적인 각속도 값이 발견됐다.

```text
angular velocity: -1593.9 deg/s
```

관절을 잠시 놓쳤다가 다시 검출하거나 프레임 사이 좌표가 튀면
작은 시간 차이로 큰 각도 변화량을 나누면서 이상치가 발생할 수 있다.

각속도는 현재 반복 횟수 판정에는 사용하지 않지만,
영상 알고리즘의 중간 측정값과 성능 검증 결과의 신뢰성을 높이기 위해 필터를 추가했다.

## 구현 내용

### 1. 유효 시간 구간 검사

다음 조건을 벗어난 표본은 각속도 계산 결과에서 제외한다.

```text
최소 계산 간격: 8ms
최대 계산 간격: 250ms
```

- 8ms 미만은 타이머 해상도나 중복에 가까운 프레임으로 판단한다.
- 250ms 초과는 이전 관절 좌표가 현재 동작을 대표하지 않는 것으로 판단한다.

### 2. 최대 각속도 제한

계산된 각속도의 절댓값이 다음 기준을 넘으면 이상치로 제외한다.

```text
최대 허용 각속도: 1000 deg/s
```

제외된 값은 임계값으로 잘라 표시하지 않고 `0 deg/s`로 처리한다.
이는 실제 측정값과 인위적으로 잘린 값을 혼동하지 않기 위한 선택이다.

### 3. 관절 인식 중단 시 기준점 초기화

다음 상황에서는 이전 각도 측정 시간을 즉시 초기화한다.

- 필수 관절 confidence 또는 좌표 검증 실패
- 관절 사이 거리가 너무 짧아 각도 계산 실패
- 화면에서 사람을 찾지 못함

관절이 다시 유효해진 첫 프레임은 새 기준점으로만 사용하고 각속도를 계산하지 않는다.
반복 횟수 상태 머신은 기존 정책대로 관절 인식이 1초 이상 끊겼을 때 초기화한다.

### 4. 이상치 제외 횟수 기록

개발자 로그에 다음 항목을 추가했다.

```text
rejected angular velocity samples
max angular velocity
```

JSON 결과에는 다음 필드를 추가했다.

```text
performance.rejectedAngularVelocitySamples
configuration.minAngularVelocityIntervalMs
configuration.maxAngularVelocityGapMs
configuration.maxAngularVelocityDegPerSec
```

CSV 결과에는 다음 열을 추가했다.

```text
rejected_angular_velocity_samples
```

## 카운트 알고리즘 영향

각속도는 개발자 진단 지표이며 현재 반복 횟수 상태 머신의 전이 조건에는 사용하지 않는다.
따라서 이번 필터는 기존 각도 임계값, 유지시간, 히스테리시스 및 카운트 결과를 변경하지 않는다.

## 실제 브라우저 회귀 테스트

다음 테스트를 수행한다.

1. 브라우저에서 `Ctrl+Shift+R`로 강력 새로고침
2. 실제 횟수에 `10` 입력
3. Right Arm Curl 정상 동작 10회 수행
4. 예측 횟수와 절대 오차 확인
5. 팔 또는 관절을 잠시 가린 뒤 다시 동작
6. 각속도가 비현실적인 값으로 유지되지 않는지 확인
7. `rejected angular velocity samples` 증가 여부 확인
8. JSON과 CSV 결과 저장

기대 결과:

```text
true reps: 10
predicted reps: 10
absolute rep error: 0
inference errors: 0
```

관절을 가린 뒤 첫 유효 프레임의 각속도는 `0.0 deg/s`가 되어야 한다.
빠른 동작 중 임계값을 넘은 표본이 발생하면 제외 횟수가 증가할 수 있지만
반복 횟수 카운트는 정상적으로 유지되어야 한다.
